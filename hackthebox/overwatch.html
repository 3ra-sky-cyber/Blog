Overwatch

Summary

Overwatch is a Windows-based Active Directory machine from Hack The Box, featuring a realistic enterprise environment with services like DNS, Kerberos, LDAP, SMB, and MSSQL exposed. It runs a non-standard MSSQL instance on port 6520 and hosts a .NET monitoring application that leaks hardcoded credentials. The machine relies on a WCF service on port 8000, which is vulnerable to command injection. Key exploitation paths involve SMB enumeration, ADIDNS poisoning, and abuse of linked servers for credential capture.

Stealing the Hash of the MSSQL Service Account

We can try steal the MSSQL service account hash using xp_subdirs or xp_dirtree undocumented stored procedures, which use the SMB protocol to retrieve a list of child directories under a specified parent directory from the file system. When we use one of these stored procedures and point it to our SMB server, the directory listening functionality will force the server to authenticate and send the NTLMv2 hash of the service account that is running the SQL Server. We need first top start Responder.

└─$ sudo responder -I tun0

Then we execute xp_dirtree on the MSSQL service.

Privilege Escalation

Lets go back a bit and inspect the code to view the various operation that are listed in the RawContent.

Looking at the KillProcess Module we see that is passing user input processName directly concatenated into a PowerShell command string.

This allows arbitrary code execution on the system with the privileges of the application.

*Evil-WinRM* PS C:\Users\sqlmgmt\Documents> $URI = "http://overwatch.htb:8000/MonitorService?wsdl"

*Evil-WinRM* PS C:\Users\sqlmgmt\Documents> $client = New-WebServiceProxy -Uri $URI -NameSpace "WcfProxy"

The New-WebServiceProxy command in PowerShell creates a client proxy to interact with the WCF service at http://overwatch.htb:8000/MonitorService using its WSDL definition. This allows calling methods exposed by the service—such as KillProcess(string)—directly from PowerShell.

When you use New-WebServiceProxy in PowerShell, it downloads and parses this WSDL to dynamically create a .NET proxy object that lets you interact with the remote service as if it were a local object. 

The -Namespace "WcfProxy" parameter assigns a custom namespace to the generated proxy class. By default, PowerShell creates a long, auto-generated namespace (like Microsoft.PowerShell.Commands.NewWebserviceProxy.AutogeneratedTypes...), which can be messy and hard to reference. 

Using a simple namespace like WcfProxy:

  • Makes the proxy object easier to reference
  • Helps avoid naming conflicts if multiple services are used
  • Improves script clarity and maintainability
